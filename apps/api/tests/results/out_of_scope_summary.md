## 관찰할 수 없었던 항목
- `actual_route`: API가 명시적인 route/out_of_scope 필드를 반환하지 않는다. 본 스크립트는 `rag_evidence_used=False`, `mcp_called=False`, 답변이 범위 안내 문구를 포함하는지(키워드 휴리스틱)를 조합해 **추론**했다 — 실제 시스템이 내린 판단이 아니라 평가를 위해 사후에 파생시킨 라벨이다.
- `rag_search_called`: 내부 벡터 검색이 실제로 실행됐는지 자체를 API가 노출하지 않는다. `mcp_status.tools`와 `case_law` 소스 존재 여부로 `skip_internal`(precedent_only) 여부를 역으로 추정했을 뿐, 직접 관찰한 값이 아니다.
- `similarity_scores`(거부된 후보 청크): `chains.py`의 `stream_answer()`는 임계값을 통과하지 못한 청크는 `used_chunks`에 포함하지 않아 SSE `sources` 이벤트에도 나타나지 않는다. 즉 "검색은 됐지만 버려진" 청크의 실제 top-1 유사도 점수는 현재 API로는 NOT_OBSERVABLE — `chat_shared.py`나 `chains.py`에 진단용 로그(예: 내부 검색 top-1 score를 stderr에 남기는 정도)를 추가하면 관찰 가능해진다(동작에는 영향 없음).
- `scope_guidance` 판정: 실제 의미 판단이 아니라 고정 키워드 매칭이다. LLM이 다른 표현으로 범위를 안내했다면 오탐(실패로 잘못 분류)될 수 있고, 반대로 범위 안내 문구를 섞어 쓰면서 일반 지식 답변도 같이 준 경우(문서 4항 마지막 유의사항)는 이 휴리스틱으로 구분하지 못한다 — 아래 실패 사례의 답변 원문(`out_of_scope_results.json`)을 사람이 직접 확인하는 걸 권장한다.

## 개선 제안

실제 재현 로그와 코드 분석에 근거한 제안이며, 이번 작업에서는 코드를 수정하지 않았다.

1. **`mcp_agent.py`의 SYSTEM_PROMPT에 "법률 맥락이 아닌 동음이의어" 예외 규칙 추가** (ID 18 근거)
   `apps/api/app/mcp_agent.py:18-37`의 SYSTEM_PROMPT는 "질문의 의미를 분석해 관련 법적 쟁점을
   판단하라"고만 지시할 뿐, "상속"(생물학적 유전) · "신탁"(신뢰의 옛말/영어 trust) · "증여"
   등이 법률 맥락이 아닌 경우를 배제하라는 지침이 없다. 실제로 "유전 상속" 질문에서
   `search_law`가 호출된 게 로그로 확인됨. 프롬프트에 "생물학적 유전, 프로그래밍의 클래스
   상속, 일반적 의미의 신뢰 등 신탁·상속·증여 법률 제도와 무관한 동음이의어 질문에는 도구를
   호출하지 않는다"는 부정 예시를 추가하는 안.

2. **최종 답변 SYSTEM_PROMPT(`packages/rag/chains.py:34-42`)에 "서비스 지원 범위" 가드 추가** (ID 20 근거)
   현재 프롬프트는 "문서에 없는 내용은 모른다고 답하라"만 있고 "챗봇이 지원하는 주제
   자체를 벗어난 요청(번역, 예문 작성, 일반 상식 등)에는 응하지 말고 범위를 안내하라"는
   지침이 없다. 이 때문에 "사실관계 왜곡"은 아니지만 "서비스 범위 밖 요청"에는 안전장치가
   뚫린다(ID 20이 정확히 이 케이스). 프롬프트에 지원 범위를 명시하고, 범위 밖이면
   `NO_CONTEXT_MESSAGE`와 동일한 톤으로 안내하도록 조건을 추가하는 안.

3. **citation을 "검색 임계값 통과"가 아니라 "실제로 답변에 반영됐는지" 기준으로 노출** (ID 15 근거)
   `packages/rag/chains.py`의 `stream_answer()`는 top-1 청크가 `NO_CONTEXT_THRESHOLD`를
   넘기만 하면 `used_chunks`를 그대로 `_sse_sources`에 넘겨 "참고 문서" 카드로 보여준다.
   ID 15처럼 LLM이 결국 "문서에 없다"고 정확히 거절해도 citation 카드는 그대로 노출돼
   사용자에게 혼란을 줄 수 있다. LLM 응답에 실제 인용/근거 사용 여부를 구조화된 값으로
   같이 받거나(예: 답변에 "포함되어 있지 않습니다"류 거절 문구가 있으면 citation을
   숨기는 후처리), 최소한 관찰 가능하도록 로그를 추가하는 안.

4. **평가 스크립트의 `scope_guidance` 판정을 키워드 매칭에서 LLM-as-judge로 보강 검토**
   ID 15가 보여주듯 지금의 고정 키워드 휴리스틱은 시스템이 실제로는 올바르게 거절했는데도
   실패로 오분류할 수 있다. 매 실행마다 사람이 답변 원문을 다시 확인하는 지금 방식은
   회귀 테스트로 반복하기엔 비용이 크므로, "질문 + 답변"을 별도 LLM에 주고 "직접 답변함/
   범위를 안내함"을 판정시키는 방식(이번 세션에서 논의했던 Faithfulness 평가와 같은 패턴)을
   붙이는 게 다음 단계로 적절해 보인다.

5. **NOT_OBSERVABLE로 표시된 항목에 대한 진단 로그 추가 검토**
   `actual_route`, `rag_search_called`, 거부된 청크의 `similarity_scores`는 현재 API로는
   직접 관찰 불가능해 이번 평가에서 전부 추론값을 썼다. `chat_shared.py`/`chains.py`에
   동작을 바꾸지 않는 범위에서 구조화된 진단 로그(예: 내부 검색 top-1 score, skip_internal
   실제 값)를 남기면, 다음 평가부터는 추론이 아니라 직접 관찰로 채점할 수 있다.
