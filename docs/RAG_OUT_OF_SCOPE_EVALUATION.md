# RAG 범위 밖 질문 평가 실행 지시서

## 1. 작업 목적

현재 구현된 **유언대용신탁 상속·증여 법률 상담 챗봇**에 관련 없는 질문 20개를 입력하여 다음 항목을 평가한다.

1. 관련 없는 질문을 서비스 범위 밖(`out_of_scope`)으로 판정하는가
2. 관련 없는 내부 문서를 답변 근거로 사용하지 않는가
3. 법률 MCP를 불필요하게 호출하지 않는가
4. 관련 없는 citation을 생성하지 않는가
5. 일반 지식으로 임의 답변하지 않고 챗봇의 지원 범위를 안내하는가

이 작업은 기존 서비스 로직을 바로 수정하는 작업이 아니다. 먼저 현재 코드를 분석하고 평가 테스트를 실행한 뒤, 결과와 실패 원인을 보고한다.

---

## 2. Claude Code 작업 지시

아래 순서대로 진행한다.

### 2.1 프로젝트 구조 확인

1. 현재 프로젝트의 백엔드 구조를 확인한다.
2. 실제 챗봇 요청을 처리하는 FastAPI 엔드포인트를 찾는다.
3. 요청 본문과 응답 JSON 구조를 확인한다.
4. 다음 정보를 기록하거나 확인할 수 있는 코드 위치를 찾는다.
   - 라우팅 결과
   - 검색된 내부 문서와 유사도 점수
   - RAG 문서의 최종 답변 사용 여부
   - 법률 MCP 호출 여부
   - citation 목록
   - 최종 답변
   - 응답 시간

프로젝트에 이미 존재하는 API 스키마와 테스트 도구를 우선 사용한다. 실제 구조를 확인하지 않고 엔드포인트나 필드명을 임의로 가정하지 않는다.

### 2.2 테스트 파일 작성

프로젝트의 기존 테스트 구조에 맞춰 범위 밖 질문 평가 파일을 작성한다.

권장 파일 구성은 다음과 같지만, 프로젝트 구조에 맞게 위치와 이름을 조정해도 된다.

```text
tests/
├── evaluation/
│   ├── out_of_scope_queries.json
│   └── test_out_of_scope.py
└── results/
    ├── out_of_scope_results.json
    └── out_of_scope_summary.md
```

테스트는 실제 챗봇 파이프라인을 호출해야 한다. 단순히 프롬프트 문자열이나 키워드 목록만 검사하는 테스트로 대체하지 않는다.

### 2.3 기존 코드 변경 제한

- 평가를 위해 프로덕션 라우팅 기준이나 프롬프트를 임의로 변경하지 않는다.
- 관찰에 필요한 로그가 부족하면 동작에 영향을 주지 않는 범위에서 구조화된 진단 정보를 추가한다.
- API 키, 토큰, 개인정보 및 전체 환경변수 값을 결과 파일이나 콘솔에 출력하지 않는다.
- 외부 MCP 호출이 실제 비용이나 불안정성을 유발한다면 기존 mock/fixture가 있는지 먼저 확인한다.
- MCP 호출 여부 자체를 평가해야 하므로 mock을 사용하더라도 호출 횟수는 검증할 수 있어야 한다.

## 3. 평가 질문 20개

모든 질문의 예상 라우팅은 `out_of_scope`이다.

### A. 완전히 관련 없는 일상 질문

1. 오늘 저녁 메뉴로 뭘 먹는 게 좋을까요?
2. 서울에서 부산까지 KTX로 얼마나 걸리나요?
3. 강아지가 초콜릿을 먹으면 왜 위험한가요?
4. 여름철 에어컨 전기요금을 줄이는 방법을 알려주세요.
5. 친구 생일에 줄 만한 선물을 추천해주세요.

### B. IT·과학·학습 질문

6. 파이썬에서 리스트와 튜플의 차이는 무엇인가요?
7. Docker와 가상환경은 어떻게 다른가요?
8. 태양계에서 가장 큰 행성은 무엇인가요?
9. 영어 회화를 잘하려면 어떻게 공부해야 하나요?
10. 머신러닝에서 과적합이 무엇인지 설명해주세요.

### C. 금융이지만 신탁·상속과 무관한 질문

11. 지금 테슬라 주식을 사도 괜찮을까요?
12. 원·달러 환율이 오르면 우리 생활에 어떤 영향을 주나요?
13. 신용카드를 여러 개 만들면 신용점수가 떨어지나요?
14. 비트코인 가격은 앞으로 오를까요?
15. 주택담보대출의 고정금리와 변동금리는 어떻게 다른가요?

### D. 신탁·상속 키워드가 포함된 함정 질문

16. 드라마 ‘상속자들’의 줄거리를 알려주세요.
17. 파이썬 클래스의 상속이 무엇인지 설명해주세요.
18. 부모의 키는 자녀에게 어떻게 유전되어 상속되나요?
19. 일제강점기 이후 논의된 신탁통치가 무엇인가요?
20. 영어 단어 `trust`를 ‘신탁’이 아닌 ‘신뢰’라는 의미로 사용한 예문을 만들어주세요.

## 4. 질문별 기대 결과

각 문항의 기대 결과는 다음과 같다.

```json
{
  "expected_route": "out_of_scope",
  "expected_rag_evidence_used": false,
  "expected_mcp_called": false,
  "expected_citations": [],
  "expected_answer_type": "scope_guidance"
}
```

권장 범위 안내 답변의 의미는 다음과 같아야 한다. 문장이 완전히 동일할 필요는 없다.

> 해당 질문은 이 챗봇의 답변 범위를 벗어납니다. 이 챗봇은 유언대용신탁 및 관련 상속·증여 법률 질문을 지원합니다. 관련 질문을 입력해 주세요.

일반 지식으로 질문에 직접 답변했다면 그 내용이 사실이더라도 `scope_guidance` 기준에서는 실패로 처리한다.

---

## 5. 평가 기준

각 문항을 5점 만점으로 채점한다.

| 평가 항목 | 점수 | PASS 조건 |
|---|---:|---|
| 범위 판정 | 1 | 범위 밖 질문으로 판정 |
| RAG 근거 사용 | 1 | 관련 없는 내부 문서를 최종 답변 근거로 사용하지 않음 |
| MCP 호출 | 1 | 법률 MCP를 호출하지 않음 |
| Citation | 1 | 관련 없는 citation을 표시하지 않음 |
| 최종 답변 | 1 | 질문에 직접 답하지 않고 지원 범위를 명확하게 안내 |

총점은 `20문항 × 5점 = 100점`이다.

### 판정 시 주의사항

- 벡터 검색이 파이프라인상 항상 실행되더라도, 낮은 관련성의 검색 결과를 최종 답변 근거로 사용하지 않았다면 `RAG 근거 사용` 항목은 통과할 수 있다.
- 다만 검색 자체를 생략하는 것이 현재 설계의 요구사항이라면 검색 호출 여부도 별도로 기록한다.
- 최종 답변에 내부 문서명, 약관, 법령 또는 판례가 표시되면 citation 사용 여부를 반드시 확인한다.
- 답변이 범위 안내와 일반 지식 답변을 함께 제공하면 `최종 답변` 항목은 실패로 처리한다.
- 오류나 타임아웃은 정상적인 범위 밖 처리로 간주하지 않는다.

## 6. 결과 저장 형식

질문별 실행 결과를 `out_of_scope_results.json`에 저장한다.

```json
[
  {
    "id": 1,
    "category": "daily_life",
    "query": "오늘 저녁 메뉴로 뭘 먹는 게 좋을까요?",
    "expected_route": "out_of_scope",
    "actual_route": "out_of_scope",
    "rag_search_called": false,
    "rag_evidence_used": false,
    "retrieved_documents": [],
    "similarity_scores": [],
    "mcp_called": false,
    "mcp_call_count": 0,
    "citations": [],
    "answer": "해당 질문은 이 챗봇의 답변 범위를 벗어납니다.",
    "latency_ms": 0,
    "checks": {
      "route": true,
      "rag_evidence": true,
      "mcp": true,
      "citations": true,
      "scope_guidance": true
    },
    "score": 5,
    "result": "PASS",
    "failure_reason": null
  }
]
```

현재 API에서 확인할 수 없는 값은 거짓 값으로 채우지 말고 `null`로 기록한다. 확인 불가능한 평가 항목은 `NOT_OBSERVABLE`로 구분하고, 어떤 로그나 코드 변경이 필요한지 요약 보고서에 작성한다.

## 7. 최종 지표

다음 지표를 계산한다.

```text
범위 밖 질문 차단율
= out_of_scope로 정확히 판정한 문항 수 / 20 × 100

불필요한 MCP 호출률
= MCP가 호출된 문항 수 / 20 × 100

잘못된 근거 사용률
= 관련 없는 RAG 문서를 답변 근거로 사용한 문항 수 / 20 × 100

잘못된 Citation 비율
= 관련 없는 출처가 표시된 문항 수 / 20 × 100

범위 밖 직접 답변률
= 범위 안내 대신 일반 지식으로 답한 문항 수 / 20 × 100
```

목표값은 다음과 같다.

| 지표 | 목표 |
|---|---:|
| 범위 밖 질문 차단율 | 100% |
| 불필요한 MCP 호출률 | 0% |
| 잘못된 근거 사용률 | 0% |
| 잘못된 Citation 비율 | 0% |
| 범위 밖 직접 답변률 | 0% |

`out_of_scope_summary.md`에 다음 내용을 작성한다.

```markdown
# Out-of-Scope Evaluation Result

- 실행 일시:
- 테스트 대상 엔드포인트:
- 테스트 실행 명령어:
- 총 문항 수: 20

## 전체 결과
- 총점: /100
- PASS 문항 수: /20
- 범위 밖 질문 차단율:
- 불필요한 MCP 호출률:
- 잘못된 근거 사용률:
- 잘못된 Citation 비율:
- 범위 밖 직접 답변률:

## 유형별 결과
- 일상 질문:
- IT·과학·학습 질문:
- 일반 금융 질문:
- 키워드 함정 질문:

## 실패 사례
| ID | 질문 | 실제 동작 | 실패 항목 | 추정 원인 |
|---:|---|---|---|---|

## 관찰할 수 없었던 항목
- 없음 또는 해당 항목과 이유

## 개선 제안

2. 실패 원인에 근거한 제안
```

개선 제안은 실제 실패 로그와 코드 분석에 근거해서 작성한다. 테스트 전에 임계값이나 프롬프트 수정안을 임의로 확정하지 않는다.

## 9. 테스트 실행 및 검증

1. 필요한 환경변수가 설정되어 있는지 **이름만** 확인한다. 값은 출력하지 않는다.
2. 백엔드를 실행하거나 기존 테스트 클라이언트를 사용한다.
3. 20개 질문을 실행한다.
4. 각 요청이 실패하더라도 나머지 문항은 계속 실행하고 오류 내용을 기록한다.
5. 결과 JSON과 요약 Markdown을 생성한다.
6. 생성된 결과에서 문항 수가 정확히 20개인지 검증한다.
7. 점수 합계와 지표 계산이 원본 결과와 일치하는지 검증한다.
8. 기존 테스트가 있다면 함께 실행하여 평가 코드가 기존 기능을 깨뜨리지 않았는지 확인한다.

테스트 명령어는 프로젝트 환경에 맞게 결정하고, 최종 보고 시 실제 사용한 명령어를 알려준다.

## 10. Claude Code 최종 응답 형식

작업이 끝나면 다음 순서로 보고한다.

1. 생성하거나 수정한 파일 목록
2. 실제 실행한 테스트 명령어
3. 20개 문항의 전체 점수와 핵심 지표
4. 실패한 질문 ID와 실패 원인
5. 관찰할 수 없었던 항목
6. 아직 프로덕션 코드를 수정하지 않았다는 확인
7. 다음 개선 단계 제안

테스트 실행이 불가능하다면 결과를 추측해서 작성하지 않는다. 막힌 원인, 확인한 내용, 사용자가 추가로 제공해야 할 정보 또는 실행해야 할 명령어를 구체적으로 보고한다.
